Signing in to the portal

What your clients will see. Real screens, not mock-ups.

Step 1 They type their email

That's all. No phone number any more.

Step 2 A code arrives

The code is in the subject line too, so it shows on a phone's lock screen without opening the email.

Step 3 They type it in

On a phone, the keyboard offers the code automatically. It submits itself on the sixth digit — there's nothing to press.

What changed underneath

Before

  • Email + phone number was the password
  • Both are findable — signatures, websites, shared contacts, data brokers
  • Anyone holding them could read a client's session history and cancel their appointments
  • Typing an email told you whether that person was a client

Now

  • The email only decides where a code is sent
  • Access needs the inbox, not two facts about the person
  • Same standard the confirmation emails already rely on
  • The page answers identically for any address

Guards on the code

✓Works once, then it's gone
✓Expires after ten minutes
✓Five wrong tries and it's discarded
✓Compared in constant time, so the comparison gives nothing away
✓Sending is capped per address, so it can't be used to flood an inbox
✓A blocked client is sent nothing at all
